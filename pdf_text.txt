1. Aim and Learning Outcomes
Real design problems have several conflicting goals, so the answer is a set of trade-offs (a
Pareto front), not one point. In this lab you will build every multiobjective algorithm taught
in Chapter 5 from scratch, run each one on realistic problems, and judge each one by
evidence.
By the end of this lab you must be able to:
1. Implement all 37 algorithms from scratch and explain in your own words what each one
actually does, step by step.
2. State the advantages and disadvantages of each algorithm, and prove them with your
own experiments (plots and numbers), not by quoting the slides.
3. Choose a suitable algorithm for a given problem using convexity, number of objectives,
variable type, constraints, preferences and budget.
4. Measure front quality with Hypervolume, IGD and Spacing.

P1 — Factory production speed (convex, 1 variable, easy)
Scenario. A factory runs one line. Faster speed lowers unit cost but hurts quality. The
plant manager wants the whole cost–quality trade-off curve, not one speed.
Variable. Production speed x, 1 ≤ x ≤ 10.
Objectives. Minimize cost f₁ = (x − 3)² and minimize quality loss f₂ = (x − 7)².
Constraints. Bounds only.
Sanity check. The Pareto set is 3 ≤ x ≤ 7. At x = 5 the point is (4, 4); at x = 3 it is (0, 16).
The front is convex: f₂ = (4 − √f₁)².
Investigate. How many weight settings give distinct points? Do equal steps in weight
give equal spacing on the front? Compare p = 1, 2 and ∞ for the weight-metric method.
P2 — Delivery fleet sizing (1 variable, real vs integer)
Scenario. A courier company decides how many vehicles to deploy. More vehicles cut
cost per delivery but add coordination delay.
Variable. Number of vehicles x, 1 ≤ x ≤ 10 (solve once with real x, once with integer x).
Objectives. Minimize delivery cost f₁ = 100 / x and minimize delay penalty f₂ = x².
Constraints. Bounds only. Every x is Pareto-optimal.
Sanity check. x = 2 gives (50, 4); x = 10 gives (10, 100). The front is f₂ = 10000 / f₁².
Investigate. Because every x is Pareto-optimal, does the algorithm keep the points
evenly spread or does it cluster at one end? What does an integer x do to the number
of distinct front points?
